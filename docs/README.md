# Документация проекта

Корневой `docs/` описывает продукт и систему в целом; `backend/docs/` и `frontend/docs/` — внутреннее устройство компонентов.

- `requirements/` — требования и критерии приёмки.
- `architecture/` — границы компонентов и взаимодействия.
- `implementation/` — технический план и этапирование.
- `decisions/` — ADR, причины выбора и компромиссы.
- `operations/` — запуск и диагностика.

Требования не смешиваются с техническими решениями. Статусы: Draft, Proposed, Accepted, Deprecated. Нереализованные возможности явно помечаются; документация реализованного поведения должна соответствовать коду.
