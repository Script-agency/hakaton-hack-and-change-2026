# Масштабирование модуля Knowledge

## Текущая архитектура

Модуль `knowledge` состоит из трёх слоёв хранения:

1. **PostgreSQL / MySQL (ActiveRecord)** — метаданные категорий, документов и частей
2. **Локальная файловая система (LocalFileStorage)** — оригинальные файлы документов и текстовые части
3. **Redis (опционально, KnowledgeCache)** — кэш текстового содержимого частей

Запросы на чтение (retrieve, список документов) выполняются через `yii\db\Query` (SELECT) и прямые вызовы `file_get_contents` для файлов.

## Производительность

### Текущие лимиты

| Параметр                        | Значение                          | Комментарий                                        |
|---------------------------------|-----------------------------------|----------------------------------------------------|
| Максимальный размер файла       | 20 МБ (по умолчанию)              | Конфигурируется через `KNOWLEDGE_MAX_FILE_SIZE`   |
| Максимальный размер части       | 1 МБ                              | Конфигурируется через `KNOWLEDGE_MAX_PART_SIZE`   |
| Максимальный inline-кэш Redis  | 256 КБ                            | Части большего размера отдаются по contentUrl      |
| TTL Redis-кэша                  | 3600 сек (по умолчанию)           | Конфигурируется                                   |
| Пагинация списка документов     | LIMIT + OFFSET (max 100)          | Стандартная, может деградировать на больших OFFSET |
| Разрешённые расширения          | md, txt, pdf, docx, html, htm     | Может быть расширено                              |

### Узкие места

1. **Одиночные индексы (status, checksum)** — фильтр по `search` (title/description LIKE) и `category_id` (через JOIN с `knowledge_part`) не имеют полнотекстового индекса
2. **OFFSET-пагинация** — на больших страницах (`OFFSET 50000 LIMIT 20`) будет сканировать всю таблицу документов
3. **Файловое хранилище** — при > 100K файлов в одной префиксной директории может снизиться производительность файловой системы
4. **Синхронное чтение файлов** — `file_get_contents` блокирует воркер до завершения чтения с диска
5. **Одиночный сервер Redis** — при высокой нагрузке на retrieve Redis может стать узким местом
6. **Отсутствие репликации read/write** — все запросы идут на один сервер БД

## Стратегии масштабирования

### 1. Добавление индексов (первоочередная мера)

```sql
-- Составной индекс для фильтрации документов по статусу + дате обновления
ALTER TABLE knowledge_document ADD INDEX idx_doc_status_updated (status, updated_at);

-- Полнотекстовый индекс для поиска по title, original_filename, description
ALTER TABLE knowledge_document ADD FULLTEXT INDEX ft_doc_search (title, original_filename, description);

-- Индекс для эффективного retrieve по is_active + sort_order
ALTER TABLE knowledge_part ADD INDEX idx_part_active_sort (is_active, sort_order);
```

### 2. Cursor-based пагинация (для больших объёмов)

При достижении > 100K документов заменить `OFFSET` на курсор:

```php
$cursor = (int)($filters['cursor'] ?? 0);
$limit = max(1, min(100, (int)($filters['limit'] ?? 20)));

$rows = $query->where(['>', 'd.id', $cursor])
    ->orderBy(['d.id' => SORT_ASC])
    ->limit($limit)
    ->all();
```

### 3. Кэширование списков документов

Для частого запроса списка документов (админка) добавить кэширование:

```php
public function listDocuments(array $filters): array
{
    $cacheKey = 'knowledge:documents:' . md5(serialize($filters));
    if ($filters['nocache'] ?? false) {
        Yii::$app->cache->delete($cacheKey);
    }
    return Yii::$app->cache->getOrSet($cacheKey, function () use ($filters) {
        // ... original query ...
    }, 60);
}
```

**Важно:** инвалидировать кэш при create/update/delete документа.

### 4. CDN или объектное хранилище для файлов

При росте объёма файлов (> 50 ГБ) рассмотреть миграцию с локальной файловой системы на:

| Решение          | Плюсы                                              | Минусы                                      |
|------------------|-----------------------------------------------------|---------------------------------------------|
| **S3 / MinIO**   | Горизонтальное масштабирование, встроенное CDN      | Дополнительный сетевой hop, стоимость       |
| **NFS / GlusterFS** | Прозрачно для приложения                          | Единая точка отказа, сложнее администрировать |
| **nginx X-Accel**| Разгрузка Yii-воркеров отдачи файлов                | Требует настройки nginx                     |

**Рекомендуемый подход (nginx X-Accel):**
1. Файлы остаются на диске, доступном для nginx
2. `AdminKnowledgeController::actionDownloadDocument()` возвращает заголовок `X-Accel-Redirect`
3. nginx отдаёт файл напрямую, не нагружая PHP-воркеры

```php
public function actionDownloadDocument(int $id)
{
    $file = $this->knowledge->documentPath($id);
    Yii::$app->response->headers->set('X-Accel-Redirect', '/protected/knowledge/' . $file['path']);
    Yii::$app->response->format = Response::FORMAT_RAW;
    return null;
}
```

### 5. Асинхронная загрузка частей (для retrieve)

При retrieve, когда много частей не в кэше, синхронное чтение с диска может занять значительное время.

**Решение — потоковое чтение:**
- Части с собственным контентом, не превышающие лимит, читаются синхронно (они уже маленькие)
- Крупные части отдаются через contentUrl (ленивая загрузка)
- Python-импортёр отдельно кэширует контент через `POST /internal/v1/knowledge/parts/{id}/cache`

### 6. Балансировка Redis

При высокой нагрузке на retrieve:

| Мера                    | Описание                                                    |
|-------------------------|-------------------------------------------------------------|
| Redis Cluster           | Шардирование ключей по нодам                                |
| Redis Read Replicas     | Основной экземпляр — запись, реплики — чтение               |
| Локальный Redis per node| Каждый сервер приложения имеет свой Redis (in-memory кэш)   |

### 7. Read Replicas для БД

Настроить Yii DB с slave-серверами:
- Все SELECT-запросы (list, retrieve) — на slave
- INSERT/UPDATE/DELETE — на master

## План масштабирования по этапам

| Этап         | Объём данных                              | Действия                                                             |
|--------------|-------------------------------------------|----------------------------------------------------------------------|
| 0 (текущий)  | < 10K документов, < 50K частей            | Без изменений                                                        |
| 1            | 10K – 50K документов                      | Добавить FULLTEXT-индекс, настроить nginx X-Accel для отдачи файлов  |
| 2            | 50K – 200K документов, > 500K частей      | Включить кэширование списков, перейти на курсорную пагинацию         |
| 3            | 200K – 1M документов, > 10M частей        | Read replicas, Redis Cluster, миграция на S3/MinIO для файлов        |
| 4            | > 1M документов                            | Партиционирование таблиц по created_at, Elasticsearch для полнотекста |
