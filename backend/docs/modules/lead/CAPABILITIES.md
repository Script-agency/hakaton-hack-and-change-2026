# Возможности модуля Lead

## Функциональные возможности

### 1. Публичный приём заявок (Intake)

Любой клиент может создать лид через единый `POST /leads`. Эндпоинт не требует аутентификации и предназначен для:
- Публичных форм на сайте
- AI-ассистента (передача истории диалога)
- Внешних систем через API

### 2. Полная валидация входящих данных

- **Обязательные поля:** компания, ФИО, телефон, резюме
- **Телефон:** проверка формата через regex (`/^\+?[0-9\s\-\(\)]{7,20}$/`)
- **ФИО:** автоматический lowercasing
- **Messages:** опциональный массив (валидация типа)
- **Дубликаты:** запрет создания двух лидов с одинаковым номером телефона

### 3. Машина состояний (State Machine)

```
                  ┌──────────┐
                  │   NEW    │
                  └────┬─────┘
                       │
                  ┌────▼──────┐
                  │IN_PROGRESS│
                  └────┬──────┘
                       │
            ┌──────────┼──────────┐
            │          │          │
       ┌────▼───┐ ┌────▼────┐     │
       │ CLOSED │ │CANCELLED│     │
       └────────┘ └─────────┘     │
              ┌───────────────────┘
              │ Из финальных статусов
              │ переход невозможен
```

- Статусы: `new` → `in_progress` → `closed` / `cancelled`
- Из `closed` или `cancelled` изменить статус нельзя (защита бизнес-логикой)
- Защита реализована в доменной сущности `Lead::changeStatus()`

### 4. Административный API

**Просмотр списка с пагинацией и фильтрацией:**

| Фильтр        | Тип      | Описание                                    |
|---------------|----------|---------------------------------------------|
| `status`      | string   | `new`, `in_progress`, `closed`, `cancelled` |
| `company`     | string   | Поиск по компании (LIKE)                    |
| `fullName`    | string   | Поиск по ФИО (LIKE)                         |
| `phone`       | string   | Поиск по телефону (LIKE)                    |
| `createdFrom` | datetime | Дата создания от                            |
| `createdTo`   | datetime | Дата создания до                            |
| `limit`       | int      | Размер страницы                             |
| `offset`      | int      | Смещение                                    |
| `orderBy`     | string   | Сортировка (по умолчанию id ASC)            |

### 5. История AI-диалога

Поле `messages` хранит полную переписку с AI-ассистентом в формате JSON-массива:
```json
[
    {"role": "user", "content": "Здравствуйте, интересует сервер..."},
    {"role": "assistant", "content": "Добрый день! Какую конфигурацию?"}
]
```

Это позволяет:
- Восстановить контекст диалога при повторном обращении
- Передать историю менеджеру для анализа
- Использовать для обучения AI-модели

### 6. Транзакционная целостность

Команды `Create` и `UpdateStatus` выполняются в транзакции через `ITransactionManager`. Это гарантирует:
- Атомарность записи лида + проверки уникальности
- Консистентность статуса при сбоях

## API-эндпоинты

### `POST /leads` — Создание лида

**Тело запроса:**
```json
{
    "company": "ООО Ромашка",
    "full_name": "иван петров",
    "phone": "+7 999 123-45-67",
    "summary": "Хочет купить сервер Intel Xeon 2xE5-2680 v4",
    "messages": [
        {"role": "user", "content": "Здравствуйте, интересует сервер..."},
        {"role": "assistant", "content": "Добрый день! Какую конфигурацию?"}
    ]
}
```

**Ответ (успех):**
```json
{
    "success": true,
    "data": {
        "id": 42,
        "company": "ООО Ромашка",
        "full_name": "иван петров",
        "phone": "+7 999 123-45-67",
        "summary": "Хочет купить сервер Intel Xeon 2xE5-2680 v4",
        "messages": [...],
        "status": "new",
        "manager_note": null,
        "created_at": "2026-11-13 12:00:00",
        "updated_at": "2026-11-13 12:00:00"
    }
}
```

**Ошибка (дубликат телефона):**
```json
{
    "success": false,
    "error": {
        "message": "Validation failed: ",
        "errors": {"phone": ["Phone already exists"]}
    }
}
```

### `GET /admin/leads` — Список лидов

**Параметры:** `?status=new&limit=20&offset=0`

**Ответ:**
```json
{
    "success": true,
    "data": {
        "items": [...],
        "total": 150,
        "page": 1,
        "pageSize": 20
    }
}
```

### `GET /admin/leads/{id}` — Детали лида

**Ответ:** один `LeadDto` в `data`.

### `PATCH /admin/leads/{id}/status` — Смена статуса

**Тело запроса:**
```json
{
    "status": "in_progress",
    "manager_note": "Перезвонил клиенту, обсуждаем конфигурацию"
}
```

## Варианты использования

1. **Форма обратной связи на сайте** — посетитель заполняет форму → создаётся лид со статусом `new`
2. **AI-ассистент** — чат-бот собирает данные → передаёт в `POST /leads` вместе с историей
3. **CRM-интеграция** — внешняя система создаёт лиды через API
4. **Работа менеджера** — просмотр новых лидов, изменение статуса, добавление заметок
5. **Отчёты** — фильтрация по статусу и дате для аналитики
