# ADR-001: PostgreSQL и границы PHP/Python

- **Статус:** Proposed — требуется подтверждение команды.
- **Контекст:** MVP включает диалоги, заявки, базу знаний, retrieval, Redis queue и transactional outbox. Backend — PHP 8.1/Yii2, генерация — Python.
- **Решение:** PostgreSQL с первого этапа; Redis — очередь/кэш, не источник истины; PHP Core владеет доменными данными; Python взаимодействует с PHP через внутренние версионированные контракты.
- **Outbox:** запись в PostgreSQL в той же транзакции, что и доменное изменение; worker публикует в Redis; consumer идемпотентен.
- **Vector search:** pgvector рассматривается, но должен быть проверен на контрольном корпусе.
- **Альтернативы:** MySQL с последующей миграцией; прямой доступ Python к общей БД; отдельный брокер с первого дня.
- **Причины:** не планировать миграцию СУБД, сохранить владение данными, ограничить межъязыковую связанность, не усложнять MVP преждевременной инфраструктурой.
- **Последствия:** нужны контракты, service auth, дедупликация и мониторинг outbox; HTTP добавляет сетевые точки отказа.
- **Открытые вопросы:** формат internal API, embedding model, retrieval strategy, гарантии очереди.
