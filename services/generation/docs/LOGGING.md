# Логирование сервиса генерации

Сервис записывает по одному JSON-объекту в строке в файл `/app/logs/generation.log` и одновременно выводит те же структурированные записи в `stdout` (поэтому команда `docker compose logs` также остаётся полезной).

## Какие события логируются

- Запуск и остановка сервиса.
- HTTP-метод, путь (без значений параметров строки запроса), статус и длительность обработки.
- Сгенерированный идентификатор запроса/корреляции: он возвращается в HTTP-заголовке ответа `X-Request-ID` и передаётся во внутренних запросах к PHP.
- Технические метаданные запроса, например количество символов и сообщений (сам вопрос и сообщения чата не записываются).
- Режим маршрутизации и количество категорий, количество найденных кандидатов, загруженных и выбранных фрагментов, количество чанков, размер контекста и длительность поиска. Сами названия категорий не записываются.
- Шаблон внутреннего endpoint PHP API, HTTP-метод, HTTP-статус, размер ответа в байтах и длительность запроса. Динамические URL источников знаний в журнал не попадают.
- Длительность вызова AI Gateway и длина ответа (текст промпта и самого ответа не записывается).
- Ошибки с указанием типа исключения и стека вызовов. Текст исключения намеренно скрывается, поскольку сторонняя библиотека может включить в него части запроса или ответа.

Логгер намеренно **не** записывает тела запросов и ответов, промпты, сгенерированные ответы, содержимое документов, HTTP-заголовки авторизации и токены. Параметры HTTP-строки запроса также не записываются. Для входящих HTTP-запросов сохраняются только известные маршруты (`/health` и `/v1/generation/chat`); любые другие пути обозначаются как `/unmatched`. Входящий `X-Request-ID` принимается только в формате UUID, иначе сервис создаёт собственный идентификатор.

## Ротация и расположение файлов

- Файл на хостовой машине Docker: `./services/generation/logs/generation.log`.
- Путь внутри контейнера: `/app/logs/generation.log`.
- Ротация: 10 МиБ на файл, 10 архивных файлов, кодировка UTF-8.
- Уровень логирования по умолчанию: `INFO`.

Подключённый bind mount сохраняет доступ к логам после перезапуска или пересоздания контейнера. Убедитесь, что каталог `services/generation/logs` существует на хостовой машине и доступен процессу контейнера для записи. Dockerfile создаёт `/app/logs` внутри образа; во время запуска контейнера этот каталог перекрывается подключённым bind mount.

## Изменения в Docker Compose

В исходном загруженном архиве не было корневого файла `docker-compose.yml`, поэтому внести изменения непосредственно в существующий Compose-файл было невозможно. Добавьте следующие параметры в уже существующий сервис `generation`. Сохраните его текущие переменные окружения и подключения томов, добавив четыре переменные окружения для логирования и bind mount для каталога логов:

```yaml
environment:
  # Существующие переменные окружения сервиса generation оставьте без изменений.
  GENERATION_LOG_FILE: /app/logs/generation.log
  GENERATION_LOG_LEVEL: INFO
  GENERATION_LOG_MAX_BYTES: 10485760
  GENERATION_LOG_BACKUP_COUNT: 10

volumes:
  # Сохраните существующие подключения каталогов scripts и data.
  - ./services/generation/scripts:/app/scripts:ro
  - ./services/generation/data:/app/data:ro
  - ./services/generation/logs:/app/logs
```

Если в репозитории для сервиса генерации используется другой путь на хостовой машине, измените только левую часть записи bind mount.

После внесения изменений в Compose выполните:

```bash
mkdir -p ./services/generation/logs
docker compose up -d --build generation
```

Просмотр логов на хостовой машине:

```bash
tail -f ./services/generation/logs/generation.log
```

Или просмотр потока JSON-логов Docker:

```bash
docker compose logs -f generation
```

## Переменные окружения

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `GENERATION_LOG_FILE` | `/app/logs/generation.log` | Путь к файлу логов внутри контейнера |
| `GENERATION_LOG_LEVEL` | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `GENERATION_LOG_MAX_BYTES` | `10485760` | Максимальный размер одного файла логов (10 МиБ) |
| `GENERATION_LOG_BACKUP_COUNT` | `10` | Количество сохраняемых файлов после ротации |

При размере 10 МиБ и 10 архивных файлах сервис сможет хранить около 110 МиБ логов на один экземпляр. Ротация выполняется с помощью `RotatingFileHandler` из стандартной библиотеки Python. Конфигурация рассчитана на один процесс Uvicorn (стандартная команда запуска в Dockerfile). При переходе на несколько worker-процессов потребуется отдельное централизованное или многопроцессное решение для записи и ротации файлов.
