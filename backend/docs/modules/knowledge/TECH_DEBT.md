# Технический долг и известные проблемы модуля Knowledge

## Баги

### 1. `actionCategory()` — неэффективный поиск категории по ID

**Файл:** `AdminKnowledgeController.php`, строка 77

```php
foreach ($this->knowledge->listCategories() as $category) {
    if ((int)$category['id'] === $id) {
        return ['item' => $category];
    }
}
throw new NotFoundHttpException('Knowledge category not found.');
```

**Проблема:** метод `actionCategory()` загружает ВСЕ категории из БД и фильтрует в PHP-цикле, вместо прямого запроса `SELECT ... WHERE id = :id`. При большом количестве категорий (> 10K) это создаёт избыточную нагрузку.

**Приоритет:** Средний
**Статус:** Не исправлено. Рекомендуется добавить в `KnowledgeService` метод `getCategory(int $id)` с прямым запросом.

---

### 2. `actionDeletePart()` — удаление части не проверяет document_id

**Файл:** `AdminKnowledgeController.php`, строка 515

**Проблема:** метод `actionDeletePart()` принимает только `$id` части, но не проверяет, что часть принадлежит какому-либо документу. При удалении части нет дополнительной валидации консистентности.

**Приоритет:** Низкий
**Статус:** Не исправлено. Валидация остаётся на уровне FK в БД.

---

### 3. Отсутствие ограничения на глубину вложенности категорий

**Файл:** `KnowledgeService.php`, метод `wouldCreateCategoryCycle()`

**Проблема:** Защита от циклов есть, но нет ограничения на максимальную глубину вложенности. Теоретически можно создать 10 000+ уровней вложенности, что приведёт к проблемам с производительностью при retrieve (BFS).

**Приоритет:** Низкий
**Статус:** Не исправлено. Рекомендуется добавить ограничение (например, 10 уровней) в `KnowledgeService::updateCategory()`.

---

### 4. `replaceDocumentFile()` — удаление старого файла при ошибке инвалидации кэша

**Файл:** `KnowledgeService.php`, строка 224

**Проблема:** При замене файла документа сначала инвалидируется кэш частей, потом сохраняется новый файл. Если инвалидация Redis упадёт с исключением, файл может быть заменён, а кэш останется со старыми данными.

**Приоритет:** Низкий
**Статус:** Не исправлено. Исключения кэша не пробрасываются выше (graceful degradation), поэтому проблема скорее теоретическая.

## Технический долг

### 1. Нет доменного слоя (Domain Layer)

**Проблема:** В отличие от модуля `lead`, в `knowledge` отсутствуют выделенные Entity и Value Object. Вся бизнес-логика напрямую работает с ActiveRecord. Это:
- Усложняет тестирование (нельзя создать сущность без БД)
- Размывает границы ответственности
- Мешает переключению хранилища (сейчас жёсткая привязка к Yii AR)

**Рекомендация:** выделить:
- `KnowledgeCategory` — Entity с полями и валидацией slug
- `KnowledgeDocument` — Entity с машиной состояний статуса
- `KnowledgePart` — Entity с валидацией локатора
- `I*Repository` — интерфейсы репозиториев

**Приоритет:** Средний

---

### 2. Отсутствие unit-тестов

Модуль не покрыт тестами:

| Компонент                    | Что тестировать                                                    |
|------------------------------|--------------------------------------------------------------------|
| `KnowledgeService`           | CRUD категорий, валидация локатора, retrieve, защита от циклов     |
| `LocalFileStorage`           | save/read/delete, path traversal защита, валидация расширений      |
| `KnowledgeCache`             | get/set/delete, graceful degradation при недоступности Redis        |
| `AdminKnowledgeController`   | Валидация multipart-загрузки, обработка ошибок                     |
| `InternalKnowledgeController` | Retrieve, кэширование, проверка ревизий                           |
| `categoryIdsWithDescendants` | Рекурсивный BFS, защита от дубликатов                             |

**Рекомендация:** добавить PHPUnit-тесты для сервиса и хранилищ. Для `KnowledgeService` — с mock-репозиторием и mock-стораджем.

**Приоритет:** Высокий

---

### 3. Нет интерфейсов для хранилищ

**Проблема:** `KnowledgeService` напрямую зависит от конкретной реализации `LocalFileStorage`. Нет интерфейса `IFileStorage`, что:
- Затрудняет переключение на S3/MinIO
- Усложняет тестирование (нельзя подставить mock-хранилище)
- Нарушает Dependency Inversion Principle

**Рекомендация:** вынести контракт `IFileStorage` и реализовать `LocalFileStorage` и `S3FileStorage`.

**Приоритет:** Высокий

---

### 4. Нет интерфейса для кэша

**Проблема:** Аналогично хранилищу — `KnowledgeService` напрямую использует `KnowledgeCache`. Хотя кэш уже имеет graceful degradation, нет интерфейса для подмены на другой кэш-бекенд (Memcached, APCu).

**Рекомендация:** вынести `ICache` интерфейс.

**Приоритет:** Средний

---

### 5. Магия в saveModel()

**Файл:** `KnowledgeService.php`, строка 662

```php
private function saveModel($model, string $message): void
{
    if (!$model->save()) {
        throw new ValidationException($message, $model->getErrors());
    }
}
```

**Проблема:** `saveModel()` скрывает детали валидации. При ошибке сохранения выбрасывается `ValidationException` с общим сообщением, а не специфичным для конкретного поля. Стандартный `Yii AR::save()` возвращает false с массивом ошибок, но сообщение в исключении не отражает конкретную причину.

**Приоритет:** Низкий

---

### 6. Отсутствие нормализации имени файла

**Проблема:** `safeFilename()` удаляет все не-ASCII символы, кроме букв и цифр. Но:
- Русские буквы сохраняются (Unicode категория `\pL`)
- Спецсимволы заменяются на `_`
- Нет транслитерации кириллицы в латиницу

Это может создавать проблемы при скачивании файлов в разных ОС.

**Приоритет:** Низкий

---

### 7. Нет Webhook / Event системы

**Проблема:** События (документ загружен, часть обновлена, категория удалена) не публикуются. Это затрудняет:
- Инвалидацию внешних кэшей (CDN, поисковый индекс)
- Уведомления (например, о новой документации)
- Аудит изменений (сейчас только updated_at)

**Рекомендация:** добавить доменные события (Domain Events) в `KnowledgeService`:
- `DocumentCreated` / `DocumentUpdated` / `DocumentDeleted`
- `PartUpdated`
- `CategoryUpdated` / `CategoryDeleted`

**Приоритет:** Средний

---

### 8. Нет валидации статуса документа при обновлении

**Файл:** `KnowledgeService.php`, метод `updateDocument()`

**Проблема:** Любое поле может быть изменено на любое значение, включая `status`. Нет проверки, что документ со статусом `archived` нельзя перевести в `draft` (или наоборот). Валидация только на уровне AR (`in` rule).

**Рекомендация:** добавить машину состояний для статуса документа (по аналогии с `LeadStatus`).

**Приоритет:** Средний

---

### 9. retrieve() — потенциально большой JSON-ответ

**Файл:** `KnowledgeService.php`, строка 417

**Проблема:** Метод `retrieve()` может вернуть тысячи частей (с inline-контентом) в одном ответе. Это создаёт риск:
- Превышения лимита памяти PHP
- Большого времени генерации JSON
- Таймаута HTTP-клиента

**Рекомендация:** добавить `maxItems` и пагинацию, а также потоковую передачу (JSON streaming).

**Приоритет:** Средний

---

### 10. Нет архивации старых ревизий

**Проблема:** При замене файла документа старый файл физически удаляется (`replaceDocumentFile()` → `storage->delete($oldKey)`). Нет возможности откатиться к предыдущей версии.

**Рекомендация:** добавить хранение N последних ревизий (с политикой очистки).

**Приоритет:** Низкий

---

### 11. отсутствие лимита на количество файлов в директории

**Проблема:** LocalFileStorage использует префиксное хранение (первые 2 hex-символа), что даёт максимум 256 поддиректорий. При равномерном распределении ключей — достаточно для сотен тысяч файлов. Но при неравномерном распределении или большом объёме может стать узким местом.

**Рекомендация:** добавить второй уровень вложенности (4 символа) при достижении N файлов на директорию.

**Приоритет:** Низкий
