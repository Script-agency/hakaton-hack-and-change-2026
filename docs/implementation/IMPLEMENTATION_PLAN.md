# Технический план реализации

Разработка ведётся вертикальными срезами, чтобы как можно раньше получить работающий сквозной сценарий.

## Рабочие направления
| Направление             | Ответственность                             | Владелец        |
|-------------------------|---------------------------------------------|-----------------|
| Архитектура и PHP Core  | домен, API, БД, миграции, outbox            | Данила Кузнецов |
| Frontend architecture   | архитектура и интеграция UI                 | Кирилл Михайлов |
| Frontend implementation | React-компоненты и сценарии                 | Михаил Некрасов |
| Python/DevOps           | generation service, workers, Docker         | Никита Покумин  |
| AI integration          | AI Gateway, провайдеры и внешние интеграции | Артём Коротаев  |

## Этап 0 — требования и данные
Инвентаризировать закрытые материалы кейса; отделить документы знаний, тестовые вопросы и примеры форматов; описать одиночные вопросы, уточнения, смену темы, новый диалог, отказ и заявку. Результат: scope, тестовые сценарии, первичная модель данных и список контрактов.

## Этап 1 — репозиторий и инфраструктура
Создать структуру, Dockerfile компонентов, Compose, PostgreSQL, Redis, `.env.example`, health checks, логи, миграции и базовый CI. Выход: чистый запуск по README.

## Этап 2 — Backend Core
Сущности Session, Message, Lead, KnowledgeDocument, OutboxMessage; миграции, репозитории, use cases, endpoints, анонимный доступ, изоляция сессий, unit/integration/API tests. Выход: история сохраняется после перезапуска, новый диалог изолирован.

## Этап 3 — AI Gateway и Python
Согласовать PHP↔Python контракт; реализовать AI Gateway, нормализацию ошибок, orchestration endpoint/worker, correlation ID, idempotency key, timeout и retry. Выход: первый сквозной ответ.

## Этап 4 — Knowledge Base и RAG
Ingestion; извлечение текста и метаданных; chunking; embeddings; индекс; retrieval; optional reranking; source references; переиндексация; контрольный retrieval-набор. Выход: контрольные вопросы находят ожидаемые источники.

## Этап 5 — консультативная логика
Состояния диалога; определение потребности; сбор недостающих параметров; уточнение; grounded answer; out-of-scope; отказ при недостатке подтверждения; краткость и понятный язык; regression tests. Выход: проходят диалоговые сценарии.

## Этап 6 — заявка
Сбор ФИО, телефона и компании; явное подтверждение; резюме; связь с сессией; просмотр заявки; идемпотентность; маскирование контактов в логах. Выход: заявка создаётся один раз и содержит нужные сведения.

## Этап 7 — frontend и интеграция
Чат, loading/error/retry, уточнения, новый диалог, форма и подтверждение заявки, интерфейс истории/заявок, debug UI, адаптивность. Выход: полный сценарий через браузер.

## Этап 8 — стабилизация и сдача
Тестовые диалоги; изоляция; сбои AI/Redis и повтор outbox; security review; чистый Docker-запуск; README, ограничения и презентация. Выход: воспроизводимая демонстрация.

## Обязательные артефакты
OpenAPI; JSON Schema внутреннего контракта; схема данных и миграции; sequence diagrams; контрольный набор; unit/integration/e2e tests; Docker и `.env.example`; ADR; список ограничений. Сроки назначаются после декомпозиции и согласования календаря хакатона.
