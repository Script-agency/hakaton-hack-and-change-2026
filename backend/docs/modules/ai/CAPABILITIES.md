# Возможности модуля AI

## Функциональные возможности

### 1. Проксирование к OpenAI-совместимым API

Модуль выступает единым прокси-слоем, скрывая от клиентов детали транспорта, аутентификации и обработки ошибок.

**Поддерживаемые провайдеры** (любой OpenAI-совместимый API):
- OpenAI (GPT-4, GPT-4o, GPT-4o-mini, o1, o3)
- Azure OpenAI
- Anthropic через OpenAI-прокси
- Ollama (локально)
- LM Studio, LocalAI
- Любой сервис с эндпоинтом `POST /chat/completions`

### 2. Два уровня конфигурации

| Уровень          | Источник                                                 | Приоритет |
|------------------|----------------------------------------------------------|-----------|
| Базовый          | ENV-переменные (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`) | Низкий    |
| Пользовательский | HTTP-only cookie (SET через `POST /ai/settings`)         | Высокий   |

Cookie-настройки переопределяют ENV. Пользователь может указать свой API-ключ без вмешательства администратора.

### 3. Переопределение модели в запросе

Поле `modelOverride` в теле `POST /ai/chat` позволяет отправить запрос на конкретной модели без изменения сохранённых настроек. Пример:

```json
{
    "systemPrompt": "Translate to French",
    "messages": [{"role": "user", "content": "Hello"}],
    "modelOverride": "gpt-4o"
}
```

### 4. Автоматические retry при rate-limit

При HTTP 429 модуль автоматически повторяет запрос до `AI_MAX_RETRIES` (по умолчанию 2) раз с экспоненциально растущей паузой (1s, 2s, ...). Если все попытки исчерпаны — клиенту возвращается HTTP 429.

### 5. Детальная диагностика ошибок

| Ответ    | Причина                                   |
|----------|-------------------------------------------|
| HTTP 429 | Rate limit провайдера                     |
| HTTP 502 | Транспортная ошибка / невалидный ответ AI |
| HTTP 504 | Таймаут соединения или запроса            |
| HTTP 500 | Внутренняя ошибка сервера (логируется)    |

Все транспортные исключения сохраняют оригинальный код и сообщение CURL-ошибки.

### 6. OpenAPI-документация

Каждый эндпоинт полностью аннотирован `#[OA_*]`, что позволяет автоматически экспортировать OpenAPI-схему для генерации клиентов и тестирования.

## API-эндпоинты

### `GET /ai/settings`

Проверка наличия/статуса настроек без раскрытия API-ключа.

**Ответ:**
```json
{
    "success": true,
    "data": {
        "hasSettings": true,
        "model": "gpt-4o-mini",
        "baseUrl": "https://api.openai.com/v1"
    }
}
```

### `POST /ai/settings`

Сохранение настроек в httponly cookie (переопределяет ENV).

**Тело запроса:**
```json
{
    "baseUrl": "https://api.openai.com/v1",
    "apiKey": "sk-...",
    "model": "gpt-4o-mini"
}
```

**Ответ:**
```json
{
    "success": true,
    "data": {
        "model": "gpt-4o-mini"
    },
    "message": "AI settings saved"
}
```

### `POST /ai/chat`

Прокси-запрос к AI.

**Тело запроса:**
```json
{
    "systemPrompt": "Ты — ассистент по продажам. Отвечай кратко.",
    "messages": [
        {"role": "user", "content": "Расскажи о продукте"}
    ],
    "modelOverride": "gpt-4o"
}
```

**Ответ (успех):**
```json
{
    "success": true,
    "data": {
        "content": "Наш продукт помогает...",
        "finishReason": "stop",
        "usage": {
            "prompt_tokens": 25,
            "completion_tokens": 50,
            "total_tokens": 75
        }
    }
}
```

## Варианты использования

1. **Чат-ассистент на сайте** — модуль принимает сообщения от пользователя, проксирует к AI и возвращает ответ
2. **AI-обработка лидов** — вызов AI через модуль `ai` из модуля `lead` для генерации summary диалога
3. **Переключение провайдеров** — быстрая смена модели через ENV без деплоя
4. **Пользовательский API-ключ** — каждый менеджер может использовать свой ключ через cookie
